# K-Drama Analytics and Prediction

A full-stack K-Drama analytics application with a Next.js frontend and a FastAPI backend. The backend loads pre-trained machine learning artifacts, reads metadata and dashboard data from PostgreSQL, and exposes prediction APIs for rating, expected viewership, and popularity.

## Features

- AI-powered K-Drama rating prediction.
- Expected watcher count prediction.
- Popularity rank and popularity level prediction.
- Autocomplete metadata for actors, directors, and screenwriters.
- Dashboard statistics for ratings, genres, platforms, release trends, and model factors.
- Swagger/OpenAPI documentation generated by FastAPI.
- PostgreSQL-backed analytics data.
- Clean backend architecture with separated routers, services, schemas, config, database, and ML artifact loading.

## Environment Variables

Copy the sample environment file:

```bash

```

Default backend variables:

```env
APP_NAME=K-Drama Analytics API
APP_VERSION=1.0.0
CORS_ORIGINS=http://localhost:3000

DB_HOST=localhost
DB_PORT=5432
DB_NAME=kdrama
DB_USER=postgres
DB_PASSWORD=123456

THRESHOLD_HOT=500
THRESHOLD_MEDIUM=1500
```

The backend uses this SQLAlchemy URL format internally:

```txt
postgresql+psycopg2://postgres:123456@localhost:5432/kdrama
```

The explicit `+psycopg2` driver keeps PostgreSQL driver resolution clear for SQLAlchemy 2.x.

## Troubleshooting

### Pylance import errors

Confirm VS Code is using the backend venv:

```bash
cd /Users/khgngx/k-drama-dacn1/kdrama-backend
source venv/bin/activate
which python
python -m pip list
```

Expected path:

```txt
/Users/khgngx/k-drama-dacn1/kdrama-backend/venv/bin/python
```

### `psycopg2` is not defined

The backend imports `psycopg2` in `app/core/database.py` and uses `psycopg2-binary` from `requirements.txt`. Reinstall dependencies if VS Code still reports the error:

```bash
python -m pip install -r requirements.txt
```

### PostgreSQL connection fails

Check that PostgreSQL is running and credentials match `.env`:

```bash
brew services list
python test_db.py
```

### Model pickle tokenizer error

The `tfidf_tag.pkl` artifact was trained with a custom tokenizer named `my_tokenizer` in a notebook. The backend registers the tokenizer before loading the pickle in `app/core/ml.py`.

### scikit-learn version warning

The checked-in model artifacts were trained with a different scikit-learn version. The app can still start, but for reproducible predictions use the same scikit-learn version used during training, ideally in Python 3.11 or 3.12.

## Development Notes

- `main.py` is intentionally kept as a thin compatibility entrypoint.
- Application creation lives in `app/main.py`.
- API routes live in `app/api/routes`.
- Business logic lives in `app/services`.
- Infrastructure code lives in `app/core`.
- Request and response models live in `app/schemas.py`.
